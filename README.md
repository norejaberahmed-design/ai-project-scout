# AI Project Scout — وكيل اكتشاف أدوات الذكاء الاصطناعي

> **🚀 افتح التطبيق مباشرة:** [كشاف الذكاء الاصطناعي — واجهة الويب](https://norejaberahmed-design.github.io/ai-project-scout/) · [حالة النشر](https://github.com/norejaberahmed-design/ai-project-scout/actions/workflows/daily-scout.yml)


تبدأ الواجهة بمحادثة بحث عربية في GitHub: تكتب ما تريد العثور عليه، فتبحث الواجهة مباشرة في GitHub Search API وتعرض المستودعات والروابط والوصف واللغة والنجوم وتاريخ التحديث. هذه طبقة بحث واسترجاع وليست نموذج LLM يولّد إجابات حرة، وتخضع لحدود GitHub العامة. وتبقى بقية التقارير متاحة من التبويبات. وهي أيضًا وكيل بحث يعمل تلقائيًا لاكتشاف المستودعات والأدوات المفتوحة المصدر في مجال الذكاء الاصطناعي على GitHub، ومراقبة نشاط التطوير والإصدارات، وإصدار تقارير عربية قابلة للتنزيل.

## ما يفعله
- يبحث عبر مجموعة استعلامات تغطي LLMs، الوكلاء، الذكاء التوليدي، الرؤية الحاسوبية، الصوت، RAG، inference، الأدوات متعددة الوسائط وأدوات البرمجة.
- يخزن المستودعات وسجل تغيّر النجوم والتفرعات في SQLite دون تصفير السجل عند كل تشغيل.
- يتابع الإصدارات المنشورة حديثًا لعدد محدود من المستودعات النشطة.
- يجمع أحدث الأوراق البحثية من arXiv في مجالات الذكاء الاصطناعي وتعلم الآلة واللغة والرؤية والروبوتات، مع الروابط والتواريخ والملخصات.
- يرتب النتائج بمؤشر تقني بسيط؛ ليس تقييمًا لجودة الكود أو الأمان أو الربحية.
- يصدر تقرير Markdown وJSON بالعربية.
- يشغل نفسه يوميًا عبر GitHub Actions، ويمكن تشغيله يدويًا من الهاتف.

## نظام المهارات القابل للتوسع

- يبحث يوميًا عن مستودعات المهارات العامة ويجمع بيانات النجوم والتفرعات وتاريخ التحديث والترخيص وملفات `SKILL.md`.
- ينشئ `reports/skills-catalog.json` و`reports/skills-catalog.md` مع درجة إرشادية شفافة ومؤشرات مخاطر. النجوم تعني الشعبية ولا تثبت جودة المهارة أو أمانها.
- يتضمن الوكيل مهارات داخلية مفعّلة في `skills/active/`: التخطيط والتحقق، التطوير المدفوع بالاختبارات، ومراجعة الأمان. يقرأ AutoDev هذه الملفات ويستخدمها إرشادات عمل أثناء اقتراح التحسين.
- المهارات الخارجية تبقى مرشحات غير مفعّلة تلقائيًا؛ لا تُنسخ أو تُشغّل أو تُضاف إلى سياق النموذج إلا بعد مراجعة الترخيص والمحتوى والملاءمة واختبارات الانحدار. أضف مهارة داخلية جديدة إلى مجلد فرعي يحتوي `SKILL.md` بعد مراجعتها.
- تظهر بيانات الكتالوج في `site/data/skills-catalog.json` بعد تشغيل سير العمل اليومي.

## التشغيل اليدوي من GitHub على الهاتف
1. افتح تبويب **Actions** في المستودع.
2. اختر **AI Project Scout Agent** ثم **Run workflow**.
3. يمكنك تغيير فكرة بحث السوق والمشتري والسوق؛ هذه حقول لمسار التحقق التجاري التجريبي، بينما يظل اكتشاف أدوات الذكاء الاصطناعي هو المسار الأساسي.
4. انتظر انتهاء التشغيل، ثم افتح تفاصيله ونزّل artifact باسم `ai-project-scout-reports-<run>`.

## تشغيل محلي (Python 3.12+)
```bash
python -m unittest discover -s tests -v
python scout.py
python ai_updates.py
python agent.py --idea "أتمتة عمل الشركات" --buyer "المدير المالي" --market "السعودية"
```
لا يحتاج إلى مكتبات خارجية. يتطلب اتصالًا بالإنترنت للوصول إلى GitHub API وBing RSS.

## الدقة وحدود الوكيل
- يكتشف ما يطابق استعلاماته العامة في GitHub؛ لا يستطيع إثبات أنه اكتشف كل أداة جديدة في العالم.
- رصد الإصدارات يعتمد على GitHub Releases، وكثير من المشاريع لا تنشر Releases.
- قد تتأثر التغطية بحدود GitHub API أو فشل الشبكة؛ راجع الأخطاء داخل التقرير.
- لا يشغّل مستودعات الآخرين ولا يثبت أنها آمنة.
- واجهة المحادثة تبحث مباشرة في بيانات مستودعات GitHub العامة، لكنها لا تستخدم نموذج LLM لتفسير كل سؤال؛ نتائجها استرجاع أولي وليست تحليلًا مؤكدًا للميزات.
- لا يدّعي أن النجوم أو التحديثات تعني نجاحًا تجاريًا أو استعدادًا للدفع.
- قرار البناء الافتراضي `DO_NOT_BUILD_YET` حتى يوجد دليل مستقل على مشكلة ومشترٍ واستعداد للدفع.

## المسار التالي
إضافة مصادر أخبار وأوراق بحثية رسمية، وتلخيص التغييرات بدليل وروابط، ثم طبقة تحليل LLM اختيارية عبر مفتاح API يقدمه المستخدم. لن يُخزن أي مفتاح في المستودع؛ يجب استخدام GitHub Actions Secrets. قبل استخدام أي API مدفوع، تحقق من التكلفة وحدود الاستخدام.


## حلقة التطوير الذاتي الآمنة
- ينشئ `self_improve.py` تقريرًا عن القدرات الناقصة والجزئية وأولويات التطوير، ويضع المستودعات المرشحة في قائمة مراجعة.
- تظهر الخطة في تبويب **التطوير الذاتي** بلوحة GitHub Pages، إلى جانب الميزات المرشحة.
- يميز النظام بوضوح بين المرشح والمقترح والمنفذ؛ لا يصف أي ميزة بأنها مدمجة دون تغيير واختبارات فعلية.
- لا يشغّل كود المستودعات الخارجية ولا ينسخه، ولا يستدعي نموذجًا مدفوعًا.
- **محرك AutoDev المحدود:** يراجع زوجًا واحدًا من ملفات المصدر والاختبارات عبر نموذج اختياري، ويقبل فقط تغيير الملفين المسموحين، ثم يشغّل الترجمة والاختبارات قبل فتح طلب مراجعة Draft. لا يدمج أي تغيير تلقائيًا ولا يشغّل مستودعات خارجية.


## التحليل الهندسي العكسي الآمن
- يفحص `reverse_engineer.py` المستودعات العامة المرشحة باستخدام بيانات GitHub وREADME وشجرة الملفات وملفات تعريف الاعتماديات.
- يستخرج إشارات معمارية، ونقاط دخول محتملة، وملفات اعتماديات، ومؤشرات تستحق فحصًا أمنيًا، ثم ينتج `reports/reverse-engineering.md` و`reports/reverse-engineering.json`.
- تظهر النتائج في تبويب **الهندسة العكسية** في لوحة الويب.
- التحليل ساكن ومحدود؛ لا يشغّل شيفرات أو سكربتات المستودعات، ولا ينسخ كودًا، ولا يفك حماية برامج مغلقة أو يتجاوز مصادقة.
- أسماء الملفات ومحتويات README أدلة أولية فقط وليست إثباتًا للأمان. لا يُدمج مشروع خارجي تلقائيًا بسبب نتيجة هذا التقرير.
- أضيف فحص PR مستقل لتشغيل مجموعة الاختبارات قبل اعتماد التغييرات.

## مسار الاستفادة من مشروع خارجي
1. اكتشاف مرشح.
2. تحليل وثائقه وبنيته وترخيصه.
3. كتابة خطة تكامل صغيرة تشرح الملفات المتأثرة والاعتماديات والمخاطر.
4. تنفيذ التغيير في فرع منفصل فقط عبر محرك توليد كود مُصرّح به.
5. تشغيل الاختبارات وفحوصات الأمان ومراجعة الفرق قبل الدمج.


## حلقة الهندسة العكسية والتحسين اليومي

تعمل مهمة **Guarded AutoDev** يوميًا على GitHub Actions. بعد اكتشاف المستودعات وتحليلها، تحاول اقتراح تحسين واحد فقط مرتبطًا بفجوة موثقة في وحدة الهندسة العكسية، مع اختبار انحدار. الإعداد الافتراضي الآن هو `reverse_engineer`؛ يمكن تغيير الهدف عبر `SCOUT_AUTODEV_TARGET` إلى `scout_core` أو `feature_hunter` أو `market_agent`.

**المطلوب مرة واحدة لتفعيل توليد الكود الفعلي:**
1. افتح **Settings → Secrets and variables → Actions** في المستودع.
2. أضف Secret باسم `SCOUT_LLM_API_KEY` يحتوي مفتاح مزود النموذج؛ لا تضعه في الكود أو في المحادثات.
3. أضف Repository Variable باسم `SCOUT_LLM_MODEL` بمعرّف نموذج متاح لديك وينتهي بـ `:free`. يرفض المحرك النماذج التي لا تنتهي بهذه اللاحقة.
4. افتح **Actions → Guarded AutoDev → Run workflow** وشغّل `run_autodev=true` لاختبار أول دورة يدويًا. بعد ذلك، تعمل المحاولة المجدولة يوميًا.

إذا لم يكن المفتاح أو معرّف النموذج موجودًا أو لم يقبل المزود النموذج، فلن يستطيع الوكيل توليد تعديل؛ يظل البحث والتحليل الساكن يعملان. النماذج المجانية وتوفرها وحدودها تتغير لدى المزود.

**حدود التنفيذ والسلامة:** يحلل الوكيل مصادر GitHub العامة تحليلًا ساكنًا، ولا يشغّل أدوات الآخرين أو ينسخ شيفرتهم. يقتصر التغيير المولد على ملف وحدة مسموح وملف اختباره، ثم تُشغّل اختبارات المشروع وفحوصات الفرق. إذا نجحت، ينشئ الوكيل **Draft Pull Request** للمراجعة؛ لا يدمج الشيفرة تلقائيًا في `main`. هذا يمنع تعديل الإنتاج بناءً على تحليل غير موثوق دون مراجعة بشرية.
